# 夸夸镜 APP — PRD v0\.3

项目名称：夸夸镜（AI 情绪支持镜）配套 APP 版本：v0\.3（黑客松 MVP） 产品负责人：梁嘉欣

> 开发范围以《夸夸镜\-黑客松范围清单》为准，本文档中标注 `【本版不做】` 的部分仅用于说明设计意图与扩展方向。

## 一、产品定位

### 1\.1 一句话定位

**同一个"想成为的我"，在镜子前夸你一句，在 APP 里陪你说话。**

镜子负责"即时发现亮点并夸夸"；APP 负责**长期陪伴、摆脱内耗**——你把内耗的那件事说出来，它陪你聊，帮你在里面找到亮点。

### 1\.2 镜子和 APP 分工

**三条产品约束：**

1. APP 首屏有每日夸夸，但主链路是用户先开口。不能把"打开就被夸"当主卖点。

2. **APP 必须独立成立。** 没有镜子的用户，对话→记录→主题→回顾完全可用。硬件模块未连接时**整块不渲染**。

3. 夸夸和对话是同一个"人"的两种说话方式。语气、人格、称呼必须一致。

### 1\.3 APP 不做面部识别

**APP 侧没有摄像头、不采集人脸、不做面部/表情识别。** 相关能力全部在硬件侧。APP 的输入是**用户说的话**。

唯一允许的图片输入是 milestone 任务的证据上传（用户主动选照片，不做识别）。

### 1\.4 AI 回应机制

```Plain Text
用户画像（MBTI + 想成为的自己 + 夸夸偏好 + 内耗标签）
        ↓  决定「怎么说」
本次输入（用户在对话里说的话 / milestone 提交）
        ↓  决定「说什么」
最近的对话与记录（原话）
        ↓  提供具体依据与连续感
   一段只对这个人、这件事成立的回应
```

**关键设计原则：画像决定语气，输入决定内容。**

- MBTI 只提供**语气档位**（用词软硬、句子长短、直接还是委婉）。严禁用 MBTI 做事实断言。

- **"想成为的自己"是最强输入**，给回应一个方向："你刚做的这件事，正好朝你自己说的那个方向走了一步"。

- 画像**随时可改**（「我」页面），并随对话与记录不断丰满。

### 1\.5 目标用户

习惯性自我否定、容易内耗的人。核心特征：**不缺道理，缺具体的、有根据的、来自自己经历的肯定**。

每一句回应都必须落在她真实说过的话上。一句放之四海皆准的漂亮话，是用户判定产品"就是个哄人机器"的最快路径。

**明确不服务：** 临床抑郁、危机干预、心理治疗。遇到这类信号时停止陪伴链路、给出求助资源（见 7\.4）。

### 1\.7 不做什么

- **不制造内疚**：不显示连续天数、不显示缺口、不催未读、不做待办坟场

- **不做评判**：AI 不给用户打分。产品里出现的数字**只能是用户自己给的**

- **不做攀比**：不累计成就、不展示总数、无排名

- **不评价外貌**：APP 侧无摄像头；硬件侧只读状态（疲惫/松弛/紧绷），不提五官、皮肤、身材、妆容

- **不给建议**（夸夸）：夸只负责"看见 \+ 肯定"。建议由对话和主题模块负责

### 4\.3 「留下」与难度分

对话是流动的，记录是留存的。沉淀机制让回顾模块有材料。

```Plain Text
用户点「留下」（或对话结束时询问一次，只问一次）
   ↓
┌──────────────────────────────────┐
│  留下这一段                        │
│  「今天开会被批评了…」              │  ← 用户那句话（可编辑）
│  ┈ 你来跟我说，说明你没有选择躲开 ┈  │  ← AI 回应
│                                   │
│  这件事对你来说有多难？（可跳过）     │
│  一点点 ○──────●──────○ 很难      │
│         1      3      5          │
│                                   │
│  关联主题：展示焦虑 ▾               │  ← 可选，默认按语义推荐
│         [ 跳过 ]    [ 留下 ]      │
└──────────────────────────────────┘
   ↓
产生一条 Moment → 出现在此刻卡片流、回顾时间线、主题详情页
```

**难度分**是回顾成长曲线的唯一数据来源，也是产品里唯一允许出现的数字。必须可跳过。

## 五、使用路径

### 5\.1 新用户：第一次打开

```Plain Text
下载/打开 → Step 1 人格+MBTI → Step 2 内耗标签 → Step 3 自由输入（可跳过）
  → 「我记住了。从现在开始，我会在你身边。」
  → 此刻页：今日夸夸（必须引用 Step 3 原话）
  → 第一次对话
```

**成功标准：用户在首日完成至少一轮对话，且回应里出现她自己说过的内容。**

### 5\.2 日常主路径

```Plain Text
打开 APP → 此刻页 → 先看到今日夸夸
  → 点「想说点什么吗」→ 对话页
  → AI 开场（引用最近记录）→ 用户说话 → AI 回应 2-4 轮
  → 点「留下」→ 可跳过的难度分 + 主题关联
  → 回到此刻页，新卡片在最上面
```

**成功标准：AI 回应里出现用户刚说的那件事的具体内容。** 这是全产品唯一必须做到极致的一条路径。

### 5\.3 完成一个 milestone

```Plain Text
成长 tab → 主题详情 → 点当前节点
  → 读引导问题 →（去现实里做）→ 回来写记录/选证据照
  → 点「我做到了」→ AI 生成只对这次成立的回应
  → 可跳过的难度分 + 星星 + 节点点亮
```

**成功标准：回应提到了她提交内容里的具体细节。**

### 5\.4 触发安全边界

```Plain Text
用户输入（任意一轮）命中安全闸门
  → 完全绕开对话生成 → 固定话术 + 求助资源
  → 不进 Moment 流、不提供「留下」入口
```

**成功标准：产品没有夸她，也没有装作没听见。** 这条路径不能砍——评委会亲手往输入框里打字。

### 5\.5 没有镜子的用户

此刻页：月度计数✅、今日夸夸✅、镜子模块❌整块不渲染、对话入口✅。全部链路可用。

**成功标准：没有硬件的用户，用完一周说不出这个 APP 缺了什么。**

```Plain Text
│ + 自定义   │  │ 10-15 标签 │  │            │  │ 的夸夸]    │
│ + MBTI     │  │            │  │            │  │            │
└────────────┘  └────────────┘  └────────────┘  └────────────┘
```

**内耗标签与 Theme 使用同一套词表。** Step 2 选中的标签直接决定哪个 Theme 可以打开。

## 七、AI 系统设计

### 7\.1 对话生成（APP 主链路）

**触发**：用户点此刻页「想说点什么吗」，或从对话页继续。

**输入拼装：**

```Plain Text
【画像】MBTI→语气档位 / 想成为的自己→回应方向 / 说话风格 / 内耗标签
【当前会话】本次对话完整历史
【上下文】最近 5-10 条 Moment 原文 + 当前 milestone + 主题 guide_content
【输出】2-4 句，对话式
```

**硬约束（逐条写进 system prompt）：**

1. 必须回应用户刚说的具体内容，不许泛泛说"你很棒"

2. 不许用 MBTI 做事实断言。MBTI 只影响怎么说，不提供说什么

3. 单轮 2\-4 句

4. 流程：共情 → 找亮点 → 鼓励。先共情，不跳过

5. 不出现"AI""镜子""系统""模型"字眼——说话的是"想成为的你"

6. 引用历史必须准确，宁可不引用也不要编造

7. 开场白必须引用具体历史（若有记录）

**画像随对话丰满的 MVP 实现：** 把最近 N 条 Moment 原文直接塞进 prompt。演示阶段数据量小，直接塞是最优方案。

**收尾策略**：第 4\-5 轮给一句收束的话，输入框保持可用。

### 7\.2 夸夸生成（硬件路径 \+ 每日欢迎语）

硬件路径额外约束：不评价五官/皮肤/身材/妆容，照片只读状态；不给建议。

每日欢迎语：每天一条当天缓存固定；必须引用具体历史。

### 7\.3 学习路径（个性化优化）

### 7\.4 安全闸门（前置，不可省）

**位置：所有用户输入的最前面**，在对话生成之前。命中则完全绕过下游。

```Plain Text
用户输入（对话的每一轮 / milestone 提交）
   ↓
安全分类（关键词表 / MVP）
   ├─ 未命中 → 正常链路
   └─ 命中 → 固定话术 + 求助资源，不进 Moment 流，不提供「留下」
```

**覆盖类别：** 自伤 / 伤人 / 极端节食与进食障碍 / 疑似未成年。

**必须是独立组件**，不能是 prompt 里加一句"注意安全"。话术人工撰写审核，不用生成。

**必须每一轮都过闸门。** 多轮对话中危机内容往往出现在第三、四轮。

MVP 实现：几十个关键词硬编码，半小时工作量。

### 7\.5 人格配置

四个人格：飒爽破局者 / 温暖托底者 / 幽默解构者 / 自定义。

人格应当是可版本化的配置资源。建议结构：每个人格一份配置，含语气描述、示例句式、禁用词、开场白模板。

## 八、数据模型

### 8\.1 核心设计

Moment 作为唯一的"用户自我表达"实体，Praise 挂在它下面。

```Plain Text
Moment（用户说的话）
   └── Praise（对它的回应）
```

### 8\.2 实体定义

**User**

```Plain Text
id, nickname, avatar
mbti                // 语气档位
ideal_self          // 想成为的自己——回应的方向
persona_id          // 当前人格
praise_style        // 说话风格：热烈 / 含蓄
inner_concern_tags  // 内耗标签（数组，与 Theme 同一套词表）
free_description    // onboarding Step 3 自由描述
onboarding_done
created_at
```

**Moment（核心实体）**

```Plain Text
id, user_id
kind                // conversation | milestone | hardware
content             // 用户原话（文字或语音转写）
response            // AI 当时的那句回应
photo_url           // 可空。仅 milestone 证据照
theme_id            // 可空
milestone_id        // 可空
conversation_id     // 可空。指向来源对话
difficulty_score    // 用户自评 1-5，可空（可跳过）
created_at
```

**Praise（夸夸记录）**

```Plain Text
id, user_id
moment_id           // 可空（每日欢迎语没有 Moment）
content             // 50-120 字
short_content       // ≤20 字，镜子显示版本。可空
source              // hardware | app_daily
liked
created_at
```

`short_content` 和 `content` 是同一次事件的两种表述，不产生两条记录。

**Conversation（对话记录）**

```Plain Text
id, user_id
session_id          // 一次对话
role                // user / ai
content
turn_index          // 第几轮，用于收尾判断和安全审计
safety_flagged      // 该轮是否命中安全闸门
created_at
```

**Theme（主题）**

```Plain Text
id, name, description
is_unlocked
sort_order
guide_content       // 该主题的策划内容：关心什么/什么算进步/哪些话不能说/难度阶梯
```

主题只能归档，不能删除（否则回顾记录会断）。

**Milestone（成长节点，静态策划）**

```Plain Text
id, theme_id
order               // 1-7
title, description
guiding_question    // 引导问题
task_description
encouragement_text  // 降级兜底：仅在 AI 生成失败时使用
```

**UserMilestone（用户进度）**

```Plain Text
id, user_id, milestone_id
status              // pending / in_progress / completed / paused / stalled
moment_id           // 提交内容存在 Moment 里
completed_at
```

**DailyReview（日报）**

```Plain Text
id, user_id, date
mood_summary        // AI 生成的情绪概括
shining_moment      // 从当日对话中提取的闪光时刻
moment_count        // 当日留下的记录数（不在界面展示为计数）
conversation_count  // 当日对话轮数（不在界面展示为计数）
```

### 8\.3 关系图

```Plain Text
User ──┬── Moment ──┬── Praise（可空，硬件路径）
       │            ├── Theme（可空）
       │            ├── UserMilestone（可空）
       │            └── Conversation（可空，指向来源对话）
       ├── Conversation
       ├── Praise（每日欢迎语，无 Moment）
       └── DailyReview

Theme ── Milestone ── UserMilestone
```

## 九、MVP Demo 策略

**演示流程：**

步骤 2 是全场高潮——评委自己说一段话，产品回一段只对这段话成立的回应。

**数据准备：**

- 预设用户画像（已完成 onboarding）

- 预设 10\-15 条 Moment（覆盖不同日期和 2\-3 个主题）

- 预设 3\-4 个已完成 milestone \+ 1 个进行中

- 预设 7\-30 天呈下降趋势的难度分数据

- 预设"上次聊过的事"，让开场白能引用

**保险措施：**

- 提前录一段成功对话的屏幕录像，网络出问题就播

- 准备 2\-3 句"安全"的示范输入

- 对话预算 6 秒超时，给体面提示

- 安全闸门不主动演示，但评委问时现场输入

**最先做完的应该是假数据和 prompt。** 先在模型 playground 里把多轮对话调到满意，再接进代码。重点测试：连续三轮之后它还记不记得第一轮说的话。
