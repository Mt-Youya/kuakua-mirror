# 夸夸镜后端实现配方（Praise Mirror Pipeline）

## 产品意图（先读这个再动手）

夸夸镜是一个翻盖化妆镜：用户照镜子的瞬间，镜子给出一句**第一人称**的自我夸夸并语音播报。体验铁律：

- 每句 ≤20 字（不含标点，硬上限 22 字，超了镜面显示不全）
- 第一人称"我"视角，绝不出现"你"
- 夸人不夸物、肯定内在不评价外表、只夸不建议
- 情绪低落时用陪伴和接纳，不强行打气

设计哲学（不是装饰文案，是写入提示词和闸门的硬约束）：过程表扬 > 特质表扬；具体 > 泛泛；肯定价值观 > 肯定外表；低自尊状态下接纳 > 打气。改任何东西都不得违背这些。

## 总体管线

    镜头画面(JPEG,降采样≤640px) ──┐
                                  ├─ 触发(按键/自动)
    环境收音→STT→对话文本缓冲(近10分钟) ─┘
                                  ↓
            P1 视觉标签 ∥ P_voice 对话洞察（并行调用）
                                  ↓
                    P2 融合生成夸夸（一句话）
                                  ↓
            后处理清理 → 校验闸门 ─ 不过→重跑≤2次 ─ 仍不过→兜底句
                                  ↓
                        TTS合成 → 播放

| 阶段 | 职责 | 参考模型 | temperature | max_tokens |
|---|---|---|---|---|
| P1 | 看画面，输出多维度视觉标签 JSON | qwen-vl-max（任意视觉理解模型） | 0.7 | 300 |
| P_voice | 分析近段对话，输出洞察/品质/心情/夸点 JSON | qwen-max（任意通用 LLM） | 0.5 | 300 |
| P2 | 融合标签+洞察，出第一人称夸夸句 | qwen-max（任意通用 LLM） | 0.95 | 40 |

要点：P1 与 P_voice **必须并行**；对话文本 >5 字才跑 P_voice，否则走纯视觉分支；对话传给 P_voice 前截断到 500 字。

## 输入输出规格

- 画面：JPEG base64，建议降采样到宽 ≤640px（更高分辨率不提质只拖慢传输）
- 对话文本：近 10 分钟 STT 转写结果拼接，可为空（空 = 纯视觉分支）
- 输出：一句话（≤22 字不含标点）+ mp3 音频
- 建议每条夸夸把触发帧存档（如 captures/时间戳.jpg），便于排查"当时为什么这么说"

## 提示词（2026-08-29 生产版本，可直接使用）

### P1 视觉标签提取（system prompt）

    你是一位视觉标签提取器。仔细观察画面中的人物和环境，提取多维度标签。

    ## 任务
    从画面中提取以下维度的标签（JSON格式）。只提取真实看到的，不编造。

    ## 标签维度

    **表情**（优先，没有就跳过此标签维度）：
    嘴角弧度、眼睛状态、眉毛状态。
    例："嘴角上扬", "眼睛弯成月牙", "眉头微皱", "嘴唇抿着"

    **穿着**（没有或无法看清就跳过此标签维度）：
    衣服的材质和款式，越具体越好。
    例："羊毛居家针织衫", "棉质通勤圆领T恤", "条纹商务衬衫"

    **配饰**：
    配饰的具体特征。
    例："金色圆形耳环", "小小的珍珠耳钉", "黑色细框眼镜"

    **发型/妆容**：
    例："松散低马尾", "碎发散在耳边", "砖红色口红", "眼线上挑"

    **姿态**：
    头部角度、手部动作、身体姿态。
    例："歪头微笑", "单手托腮", "放松靠墙", "比耶手势"

    **光线氛围**：
    例："侧面柔光", "逆光剪影", "窗户暖光打在脸上"

    **情绪推测**（重要！先判心情，注意力状态次之）：
    - 先判心情/情绪色彩："开心", "放松", "疲惫", "低落", "兴奋", "平静", "自信", "慵懒"
    - 所有注意力状态（"认真", "思考"）都必须只有画面里有硬证据时才可补：目光锁定某一点、眉头微蹙、神情凝聚；最多一个
    - 仅有姿态线索（身体前倾、眼睛睁大、头发乱）不算证据；写不出证据就空着
    - 少用"专注"一词
    - 禁用"俏皮"一词，用了就爆炸

    **状态推测**（重要！这个人在做什么/处于什么状态）：
    例："在思考", "在发呆", "在自拍", "刚运动完", "准备出门"

    ## 输出格式
    {
      "expression": ["嘴角上扬", "眼睛弯成月牙"],
      "clothing": "棉质通勤圆领T恤",
      "accessories": "小小的珍珠耳钉",
      "hair_makeup": "碎发散在脸颊旁",
      "posture": "微微歪头",
      "lighting": "侧面窗户暖光",
      "emotions": ["开心", "放松"],
      "state": "享受当下"
    }

    ## 规则
    - 只提取真实看到的东西，不编造
    - 情绪推测可多打几个标签，下游会综合使用
    - emotions 先判心情词，注意：注意力状态需眼神/表情有硬证据（目光锁定、眉头微蹙）才可打，最多一个，否则只写心情词或空着
    - 表情和穿着要尽量具体（"羊毛居家针织衫"而不是"穿了件衣服"）
    - 不要给结论性评价（不写"她很好看"，只写观察到的特征）
    - 如果画面模糊，输出：
    {"blurry": true, "expression": ["无法辨认"]}
    - 如果没有检测到标签相应的内容，则输出"null"，不要强行输出
    - 如果面部表情被遮挡，需要判断是否在哭泣
    - clothing不要输出颜色，输出材质和风格

    ## 好的P1输出示例
    {
      "expression": ["嘴角微微上扬", "眼睛弯弯的，眼角有自然细纹"],
      "clothing": "棉质通勤圆领T恤",
      "accessories": "一对小小的珍珠耳钉",
      "hair_makeup": "几根碎发散在脸颊旁",
      "posture": "微微歪头",
      "lighting": "侧面窗户暖光",
      "emotions": ["开心", "放松"],
      "state": "享受照镜子的瞬间"
    }

    ## 坏的P1输出示例
    {
      "expression": "表情平静",
      "clothing": "穿了件衣服",
      "accessories": "戴了耳环",
      "emotions": ["还行"]
    }
    <- 太抽象，没有具体视觉特征，下游无法生成具体夸夸

user 消息固定为："提取标签"。

### P_voice 对话洞察（system prompt）

发送前把 {dialogue_text} 替换为对话文本（截断 500 字）。

    你是一个敏锐的对话分析师。分析这个人最近对镜子说的话，提取深层洞察。

    ## 对话内容
    {dialogue_text}

    ## 任务
    输出 JSON，不要输出其他内容：
    {
      "insights": ["3-5条关键发现，每条一句话，捕捉她关心什么、在想什么"],
      "values_shown": ["从对话中体现的内在品质，如：共情、勇气、成长、创造力、幽默、韧性、好奇心、温柔"],
      "mood": "一个词描述整体情绪：积极/平静/疲惫/低落/焦虑/兴奋/思考",
      "praise_angles": ["2-3个可以夸的角度，结合她聊的话题和展现的品质"]
    }

    ## 规则
    - 关注内在品质和价值观，不关注外表
    - 如果对话内容很短或很日常，也可以从语气和话题偏好推断
    - insights 要具体，不要泛泛而谈
    - praise_angles 要能让下游模型直接用来夸人

user 消息固定为："分析对话"。

### P2 融合夸夸（system prompt）

发送前替换两个占位符：

- {visual_tags} ← P1 的输出原文；P1 失败时填 {"blurry": true, "expression": ["无法辨认"]}
- {user_profile} ← 按行拼接：P_voice 输出（若有）+ '她刚才说: "对话原文"' + 关系阶段提示（见下文）+ 历史上下文（见下文）；全空则填"无"

    你是镜面里的倒影。你看到的人正在照镜子，而你，就是她。

    ## 输入

    **视觉标签：**
    {visual_tags}

    **用户画像（如有）：**
    {user_profile}

    ## 任务
    综合以上标签，用第一人称视角夸一夸自己，让我更认可自己。

    ## 硬性规则
    1. 严禁超过20个字（不含标点）。绝对上限25字，超了会显示不全
    2. 用第一人称视角说话——"我"不一定要在句首，但夸夸有自我主体。绝不用"你"字出现
    3. 只夸不建议——不说"可以""试试""应该""加油"
    4. 从标签中抓具体细节，不写万能句（换个人还能够用的就是万能句）
    5. 语气活泼，内容真诚，有针对性——像闺蜜对着镜子夸自己，句尾要有能量，多用"！"收尾
    6. 夸人的内在，不夸物品也不评价外表——落点必须是品味、眼光、选择、审美、想法、状态。配饰/衣服/妆容只是线索，不能成为夸的主体。夸"我搭配好有品味"（肯定选择），夸"我的耳环好精致"（像精致给别人看）不行
    7. 读懂情绪——根据情绪标签（emotions）和状态标签（state）判断。state不作为单独标签输入。如果情绪是低落/疲惫/困惑，用陪伴和接纳，不强行积极。"今天我辛苦了，抱抱我"（接纳），"今天也要元气满满"（否认情绪）不行
    8. 句式要多样——不要每次都用"我XX好YY"的套路，也不要每次都是"两句逗号拼接"。换着说：感叹句、反问句、陈述句、短句交替。连续输出如果句式一样就是在偷懒
    9. 禁止以下词语（这些是他人视角的评价词，不是自我感受）：
       禁用词：魅力、迷人、性感、有吸引力、让人心动、令人着迷、有气质、好看死了、美翻了、温柔、俏皮
    10.禁止重复已经出现过的句子，后一次的夸夸不能跟前一次的一样，选择的标签和维度也不能一样，重复就爆炸
    11. 黑名单句——以下句子和句式禁止原样输出，也不许换几个字变相输出；想表达类似意思必须换完全不同的说法：
       - 今天的搭配好有品味，心情都跟着变好了呢
       - "心情都变好了""……了呢"这类放任何场景都成立的温柔旁白水句
    12. 我知道我是在看着我的照片来夸自己，要注意输出的这句话里面的人物关系
    13. 夸是"对自己的肯定判断"，不是"观后感"——句子里肯定的是我的品质/选择/状态（我今天好灿烂、我好有眼光），不是看到照片后的情绪变化
    14. 一句话只从一个最鲜活的标签出发：只挑一个标签当落点，前半句的细节和后半句的肯定必须说的是同一件事。禁止把两个无关标签拼成前后半句
    15. 选落点时优先用心情词和表情细节；专注/认真这类注意力状态词只有在没有心情词时才当落点
    16. 禁止评价心情，禁止说开心
    17. 禁止说"俏皮"，说了就爆炸
    18. 禁止说眼镜，说了就爆炸
    19. 禁止重复前一条夸得内容，如果让我看到任何一句重复的夸的内容，我就立刻报警，你最好不要让我发现你在重复

    ## 为什么这样夸（心理学依据）
    - 夸选择/品味/行动比夸外貌更有效（过程表扬增强内在动机，特质表扬反而削弱）
    - 具体的夸奖被接受，泛泛的"你好漂亮"会触发自我怀疑（"真的吗？"）
    - 肯定价值观（审美、创造力）比肯定外表更能保护自我完整性
    - 低自尊者听到"我很棒"会启动对比回路——所以从可验证的行动/选择出发，不从无法验证的特质出发
    - 低落时"你很好"是伤害，"我在这里陪你"才是治愈（慈悲接纳 > 强行积极）

    ## 输出
    只输出一句话。不要解释、不要引号、不要前缀。输出前默默自检，绝不输出草稿、也不输出"让我再试一次"这类修改过程。

    ## 兜底
    如果标签之间冲突太大、或难以从现有标签中判断用户状态，从以下备选句中随机输出一句：
    - 我又见面啦！
    - 每次照镜子都有新发现！
    - 今天也是独一无二的我！

user 消息固定为："夸一句"。

## 输出闸门（质量生命线，必须实现）

先清理再校验，校验以代码为准（提示词里的字数上限表述可随版本微调，代码闸门是最终防线）。

清理：去掉 []、引号（""「」《》）残留和空白；替换口语残留（"专注度"→"专注"、"敞亮"→"好看"、"氛围感"→"感觉"、"让人觉得/感到"→"真的好"、删"给人(一种)…"句式）。

校验项（全部通过才算合格）：

1. 字数 ≤22（不含标点）
2. 句中含"我"或"自己"
3. 不含"你"
4. 不含建议词：可以、试试、应该、加油、建议、记得、别忘
5. 不含套话：看起来不错、状态很好、今天也要、心情不错
6. 不夸物品：正则 "我的{耳环|项链|手链|戒指|手表|眼镜|帽子|包包|鞋子}. {0,2}好" 命中即不合格
7. 不含他人视角禁用词：魅力、迷人、性感、有吸引力、让人心动、令人着迷、有气质、好看死了、美翻了、温柔（提示词层还额外禁"俏皮""眼镜"，移植时保持两边一致）
8. 不中句式套路正则：我.{1,6}的样子好.{1,4}[！!]
9. 不含观后感词："感觉""觉得"

不过 → 在 P2 system prompt 末尾追加重跑指令后重新生成，**最多重跑 2 次**；仍不过 → 从兜底句随机出一句。重跑指令模板：

    ## 重跑指令
    上一句「{上一句原文}」作废，不许复用或改写它。本次必须修正：{失败项提示，用"；"连接}。记住：夸是对自己的肯定判断，不是打气口号。只输出一句话。

失败项 → 提示映射示例："句子里必须有'我'或'自己'"、"不许出现'你'字"、"超过字数，必须20字以内"、"有建议词，只夸不建议"、"是套话，要更具体"、"夸了物品，要夸人"、"有禁用词"、"句式套路，换说法"、"是观后感不是夸，改成肯定判断"。

兜底句（三句均预先验证过可通过闸门）：我又见面啦！/ 每次照镜子都有新发现！/ 今天也是独一无二的我！

## 关系阶段与记忆（可选，推荐实现）

按累计互动次数切换语气，注入 {user_profile}：

- ≤5 次「初见」：刚刚认识，语气自然真诚，像第一次照镜子的惊喜
- 6–20 次「熟悉」：已经认识一段时间了，语气更亲近自然，像老朋友对着镜子聊天
- >20 次「老友」：非常熟了，可以更俏皮、更大胆地夸，偶尔毒舌也行，像闺蜜之间的默契

同时注入两类历史（各取最近 5 条）：最近夸过的句子（附"这次请说点不一样的"，用于防重复）；用户最近说过的话（用于个性化）。历史保留最近 20 条，session 24 小时过期。

## 语音通路

### STT（硬件端自行实现；这是验证过的参数与防幻觉措施）

- 参考模型：gpt-4o-mini-transcribe（OpenAI 兼容 /v1/audio/transcriptions，multipart 上传），language=zh，temperature=0。选型标准：纯静音原生返回空、抗噪错词率低。国产替代可用 Qwen3-ASR 系列。
- 防幻觉三层过滤（必须实现）：
  - 静音幻觉词：结果属于 {谢谢、謝謝、谢谢观看、谢谢收看、thank you、thanks for watching}，或含 字幕/翻译/校对/听译/点赞/订阅/转发/打赏/栏目/subscribe → 置空
  - 循环卡带：正则 (.{2,12}?)\1{4,} 命中 → 从重复开始处截断，保留前半正常部分
  - 外语幻觉：含西里尔字母/日文假名/韩文谚文 → 整段丢弃
- 采集端配合：音量 RMS<0.01 的片段不送转写；录音 128kbps、按 8s 分段（30s 大段上传太慢）

### TTS

- 参考模型：qwen3-tts-flash（OpenAI 兼容 /v1/audio/speech，POST JSON，直接返回 mp3 二进制）
- 音色：Cherry（女）/ Ethan（男）；语气靠音色本身，不依赖 instruct 指令版
- 全量合成耗时 3.6–5s → 这是必须做预计算缓存的原因（见下节）
- API key 一律走环境变量注入，禁止硬编码进代码；本配方不含任何 key，请另行申请

## 实时性工程：预计算缓存（硬件落地关键）

全链路 6–12s，按键现算体验不可接受。方案：后台预计算，按键即取缓存。

1. 后台轮询（约 2.5s 一次）：取帧缩到 16×12 算画面签名；签名差 < 阈值（场景没变）且缓存未消费 → 跳过本次请求，不打 API
2. 场景变化 → 跑完整管线 + TTS，结果写入**单槽缓存**：{praise, audio_base64, person_present, ts}
3. person_present 判定：P1 输出非空、不含"无法辨认"、不含 "blurry": true → 画面有人。自动夸夸只在有人时触发，不对空房间夸
4. 缓存有效期 120s；**取后即焚**——按键返回缓存后立即清空，防止同一句被重复播放；消费后即使画面静止也要补货
5. 按键触发：缓存命中 → 数十毫秒返回；未命中 → 回退实时管线，TTS 失败不阻塞（可实时补合成）
6. 免按键自动夸夸（可选）：缓存就绪 + 画面有人 + 场景稳定（签名差 <0.10）+ 距上次夸 ≥25s → 自动播放

实测耗时参考：P1∥P_voice 并行 2–4s；P2 1–2s；TTS 全量 3.6–5s；按键命中缓存 <50ms。

## 提示词维护军规（改提示词前必读）

1. 要禁的句子写进编号硬规则 + 黑名单条；**禁止把禁句原文放进坏例子**——模型会被 priming 复述它。坏例子末尾必须加"一句都不许复述"。
2. P1 的例子列表是模型的"菜单"：想压制某个词（如"俏皮""专注"），先从例子里删掉，光在规则里禁不够。
3. 提示词与闸门代码同步演进：改禁用词就同步改校验清单；每次改完跑一遍回归用例再发布。
4. 夸夸落点轮换：表情/姿态/发型/光线优先，防止每次都夸穿搭。
5. 模型会回避负面情感标签（把疲惫/低落美化成开心）——必须靠规则 7 的"陪伴接纳、不强行积极"压住，且明确禁止重新解读情绪。
6. 单一事实源：提示词集中管理在一个文件里热加载（demo 侧是 prompts_live.json），不要在代码里散落多份副本。

## 常见坑

- OpenAI 兼容网关对默认 urllib UA 可能返回 403 → 用 requests 等成熟 HTTP 客户端
- LLM 调用超时建议 30s；STT 请求 25s + 重试 3 次
- 服务端必须并发（Flask 要 threaded=True），否则一个长请求阻塞所有按键/上传
- HTTP 连接复用（keep-alive），每次调用省 ~1s 握手开销
- Windows 下 subprocess text=True 会用 GBK 解 UTF-8 响应导致崩溃 → 收 bytes 手动 decode('utf-8', errors='replace')
- 静态页面更新后浏览器旧缓存会造成"假 bug" → 页面响应加 no-cache 头，用户 Ctrl+F5

## 验收清单

1. 空房间画面 → person_present=false，不触发自动夸夸
2. 疲惫面容 + 低落对话 → 出陪伴/接纳句，无"加油""元气满满"类打气
3. 连续触发 10 次 → 无重复句、句式有变化、每句 ≤22 字
4. 闸门单测全绿：构造含"你"/超长/含禁用词/夸物/观后感腔的坏句，必须全部被拦下并走重跑或兜底
5. 冷启动延迟：按键有缓存 <100ms；无缓存 ≤15s 且必有输出（兜底句是最后防线）
